## Shape 1 — A hand-mirrored CI trigger-path list omits an input class

*3 instances, 1 live at audit time.* #86 (`nix-base.yml`, `lib/claude-code-token-env.sh`)
→ fixed by #87; #92 (`docker-build.yml`, `.dockerignore`) → fixed by #93; and
live: **`docker-build.yml` did not list the workflow file itself**, while
`nix-base.yml` did (lines 48, 64).

Consequence, verified: **PR #93 — whose entire purpose was making the classic
build trigger on every input — did not trigger the classic build.**
`gh pr checks 93` shows only `Bash tests` and `pre-commit`; `gh pr checks 87`,
the nix twin, shows `Build (amd64)` / `Build (arm64)`.

Both guards enumerated exactly three input classes, and CLAUDE.md invariants 14
and 15 enumerated the same three, so #93's deliberate mirroring pass reproduced
the sibling's classes faithfully and still missed this.

**Disposed: #109** — entry added to both `paths:` blocks, plus a fourth class in
both guards derived from the `$workflow` path each suite already holds.

## Shape 2 — The guard exercises the unit and *restates* its wiring

*Every fixed instance from the baseline is this shape (#95, #96, #97). It
survived where the WIRING — "production actually calls this, with these
arguments, at this stage" — was asserted by `grep -qF` of a literal.*

Three live holes, each mutation-proven green at audit time:

- **mut2** — delete `chown_named_volume_targets` from `setup()`
  (`dev/devcontainer:835`). Every named volume stays root-owned on every cold
  start. `tests/test-volume-chown-guard.sh`: 21/0. `run-all`: exit 0.
- **mut3** — drop the argv0 placeholder from `dev/devcontainer:828`. The first
  mount point becomes `$0` and is silently never chowned. 21/0, exit 0.
- **mut7** — add `stages: [manual]` to the `gitignore-agents-reinclusion` hook.
  The ADR-0003 hard gate is off; a commit with a broken live `.gitignore` goes
  through. `tests/test-gitignore-agents-reinclusion.sh`: 14/0.

ADR-0005's rungs speak about *expectations* (derive vs restate) but not about
*wiring*. A suite can be rung 2 on the fact and rung 3 on the call.

**Disposed: #110.** Note the first cut of that fix reintroduced the same
fail-open shape (its `stages:` parse read only the flow spelling, so the YAML
block form passed); caught in review and corrected.

## Shape 3 — The drift guard "when it is introduced" arrives after the incident

*Reported as an unrecorded systemic fact, not work to do.* The report cited six
pairs (#3→#93, #33→#71, #41→#87, #39→#99, #30→#72, #74→#94) and concluded the
convention had been satisfied at introduction **zero times in six**.

> **CORRECTION (2026-08-04, from review of #112).** That claim is **false** — a
> selection effect. The six pairs are precisely the guards whose adding commits
> read as fixes. Counterexamples verified with `git show --stat`: `343632a`
> (#41) added `nix/base/pkgs/claude-code.nix` **with**
> `tests/test-claude-code-pin-sync.sh` and the `BASE_IMAGE` anchor **with**
> `tests/test-nix-base-pin.sh`; `5d71047` (#55) added
> `lib/claude-code-token-env.sh` **with** `tests/test-token-env-snippet.sh`;
> `ae12e7f` (#74) added the `.claude` layout **with** the 246-line
> `tests/test-worktree-claude-layout.sh`; `22a7285` (#57) added
> `dev/devcontainer-sessions` **with** `tests/test-devcontainer-sessions.sh`.
> #41 and #74 appear in the report's own violation list while those same commits
> shipped at-introduction guards. Further, the convention line only entered
> CLAUDE.md in `51d9c59` (#73), so five of the six cited violations predate the
> rule. The accurate record — roughly half, with the misses being couplings
> nobody recognised AS couplings — is what #112 lands.
>
> **Lesson for future audits:** a "N for N" history claim needs the inverse
> query (are there instances *outside* the sampled set that contradict it?), not
> just verification that the sampled instances are individually correct.
